# TalkCapture

Report Photo Organizer

[中文](README.md) · [English](README.en.md)

Turn photos of presentation slides into an image-based PowerPoint deck or PDF.

Built for people attending academic talks, research presentations, and conferences, TalkCapture helps collect slide photos, locate the projected screen, correct perspective, review page order, and export a document for later reference. It supports desktop import, optional phone transfer over a trusted local network, and batch processing while preserving original files and manual adjustments.

The current version is **0.1.0, a local development release**. The core workflow is implemented. Real photo batches, physical phone workflows, large high-resolution collections, and compatibility with everyday presentation software still require acceptance testing. It has not been publicly deployed or integrated with Pulse.

Source backup: [private GitHub repository](https://github.com/jizw0704-source/talkcapture). Repository access requires permission. Local photos and browser editing projects are not included in this backup.

## Features

| Feature           | Current behavior                                                                                             |
| ----------------- | ------------------------------------------------------------------------------------------------------------ |
| Import            | JPEG, PNG, HEIC / HEIF; up to 100 photos, 30 MB each, 1 GB total                                             |
| Phone transfer    | QR pairing on trusted Wi-Fi with desktop approval; one phone for up to 10 minutes                            |
| Image correction  | Local geometric screen detection, perspective correction, manual corners, rotation, brightness, and contrast |
| Page organization | Reorder, exclude, restore, and move pages in batches; preserve manual edits                                  |
| Batch generation  | Explicitly start automatic organization; review uncertain pages before continuing                            |
| Export            | Image-based PPTX / PDF, 16:9 or 4:3, with quality or file-size priority                                      |
| Project recovery  | Cache original files and editing metadata locally; restore after refreshing once saved                       |

Each exported PowerPoint slide contains an image. Editable text and charts, deduplication, and recovery of obscured content are not currently supported. Screen detection uses local geometry. The new report workspace uses macOS Vision OCR and conservative grouping suggestions, editable groups/text, and source-cited Markdown excerpts. Optional MiniMax cloud interpretation sends only the selected report’s recognized text and requires a server-side API key; real multi-talk grouping and summary quality still need acceptance testing. See the [usage guide](docs/usage.en.md).

## Quick start

Requirements: Node.js 24 and pnpm. Keep the existing lockfile and dependency patch.

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm start
```

Open <http://127.0.0.1:9015/?auto-crop=1>. The interface supports 中文 and English; choose your language in Settings. To explore the workflow, choose “体验示例” (Try demo). Demo images are generated by the application.

1. Select photos on the computer, or choose “手机传图” (Phone transfer), scan the QR code, and approve the connection on the desktop.
2. Wait for all photos to arrive, then choose “自动整理并生成 PPT” (Automatically organize and generate PPT). Existing page order and manual adjustments are preserved.
3. If “需要检查” (Needs review) appears, inspect each listed page, confirm its corners or exclude it, then continue generation.
4. Download and inspect the file. For PDF export or manual page-by-page work, use “核对画面 → 导出报告” (Review images → Export report).

## Development checks

```sh
pnpm format
pnpm format:check
pnpm typecheck
pnpm test
pnpm build
pnpm test:browser
pnpm start
```

Use `pnpm dev` while editing source files. `pnpm preview` runs the same service as `pnpm start`. All three use port 9015 and cannot run simultaneously. Browser tests require Playwright Chromium and start an isolated built service on ports 9025/9026 without reusing the user’s transfer session. Standalone ESLint is not configured.

## Local data and privacy

Image correction, previews, and document generation run in the desktop browser. Original files are not overwritten. The browser database caches original files separately from editing metadata. Once saving completes, refreshing restores the originals and edits. Legacy entries or cleared browser data may require supplying the originals again.

Phone transfer is optional and only starts when explicitly enabled. Its local HTTP connection is unencrypted, so it is suitable only for non-sensitive material on trusted Wi-Fi. It must not be exposed to the public internet. Phone files are temporarily stored on the computer during transfer; abnormal termination may leave temporary files. See the [user guide](docs/usage.en.md) for details.

The repository contains source, tests, documentation, lockfiles, and the dependency patch. Real photos, generated PPT/PDF files, browser project data, credentials, local environment files, and test artifacts stay outside version control.

The Settings panel configures the MiniMax model and server-side API key, tests saved credentials using a fixed message, and provides light/dark/system themes, three text sizes, app version and build time. Existing keys are never returned to the page. Display preferences stay in the current browser.
