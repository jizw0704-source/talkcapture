# 工程结构与维护

## 运行与技术栈

项目是独立本地工具，前端使用 TypeScript、Vite、Canvas 和浏览器 Worker；Node.js 24 提供本地静态服务与可选手机传图网关。图片处理使用 exifr、heic-to，文件生成使用 PptxGenJS 和 jsPDF，二维码由 qrcode 在本机生成。文字识别使用本机 macOS Vision；可选 MiniMax 解读是显式调用的云端文字分析。应用不下载本地模型，也没有分析埋点。

使用 pnpm 和仓库内的 `pnpm-lock.yaml`、`pnpm-workspace.yaml`；具体安装、启动、格式、类型、测试和构建命令见 [README](../README.md#开发检查)。不随意升级依赖或切换包管理器。

## 主流程与可选批量路径

主流程：手机或电脑导入 → 全部照片自动建议四角和预览 → 人工核对 → 本机 OCR 建议分报告与命名 → 核对分界 → 按组导出 PPTX / PDF / 原文 Markdown。普通导入不会自动确认或自动导出。手动导出未确认页面时，必须由用户明确选择按原图输出。

批量路径：用户点击自动整理 → 按当前页序处理保留页面 → 沿用已有四角和人工参数 → 没有四角才尝试定位 → 几何校验 → 逐页校正 → 全部保留页就绪后生成 PPTX。

批量处理中，缺图、多个候选、没有完整边界、无效四角或处理失败会集中列入“需要检查”；成功页保留，整份文件暂停生成。取消不提交当前未完成页，已完成页面和已有编辑保留。第三方文件封装不能立即中断，但取消后丢弃结果。

## 照片与状态

- 原始文件保持不变。自动分析最长边为 640 px，校正预览为 1400 px，原图对比预览为 1800 px。
- 最终导出重新读取原文件；清晰优先为最长边不超过 3200 px、JPEG 质量 95%，体积优先为 1920 px、82%。不放大低分辨率原图。
- `processed` 表示已完成校正；`automated` 用来区分工具自动校正与人工确认。界面不能把自动结果标作人工确认。
- IndexedDB v2 保留原 `project` store，并新增 `originals` store。原图以页面 ID 为键保存 Blob 与 SHA-256 指纹；编辑保存不重复写整张原图。写操作串行，成功事务完成后才更新缓存状态。恢复时校验页面指纹和文件大小，防止失败的替换写入关联到旧缓存。清空项目在一个事务中删除参数与缓存副本。
- 排除页面只是从输出中移除。取消、重试和恢复项目不得覆盖人工调整或删除原图。

## 本地服务边界

电脑页面固定监听 `127.0.0.1:9015`。用户点击生成二维码后，手机网关才在所选私有网络地址的 9016 端口开启；手机申请连接后仍须电脑批准。网关限一台手机、10 分钟、100 张 / 1 GB，单张 30 MB，并遵守项目累计容量限制。

手机文件暂存在系统临时目录，以随机文件名和受限权限保存。导入确认或拒绝、关闭、过期和正常停止服务会清理本次暂存；强制终止或断电可能留下临时文件。HTTP 传输未加密，不能当作公网上传服务。具体使用与排查见 [使用方法](usage.md#手机扫码传图本地体验版)。

## 依赖补丁与检查

`patches/pptxgenjs@4.0.1.patch` 修复导出库为每页声明不存在母版文件的问题，只声明实际存在的 `slideMaster1.xml`。pnpm 根据工作区配置自动应用补丁。保留补丁和锁文件；浏览器回归会检查内容类型引用的文件真实存在。

`core-js` 的可选安装后脚本在工作区配置中禁用。新增生产依赖必须确有需要，并记录原因。

浏览器测试使用独立的 9025/9026 构建服务；先构建，再运行测试，不另行启动或复用 9015。无私有 IPv4 网卡时手机测试可能跳过，必须如实记录。图像和导出检查文件保存在被忽略的 `test-results/`，不提交到仓库。

## 仓库维护

提交前检查改动与暂存文件，运行 README 中的检查。源码、文档、测试和补丁可以提交；真实照片、连接凭据、临时文件、导出文件、环境文件和依赖目录留在本地。修改界面时遵循项目所有者的 Pheno Design Language v1.4，并实际核对桌面与窄屏。

本仓库用于版本管理和备份。创建仓库不表示发布应用；公网部署、第三方上传、Pulse 对接和扩大手机网关访问范围都需要独立确定方案。

### 浏览器测试隔离

先运行 `pnpm build`，再运行 `pnpm test:browser`。测试自动启动构建服务于 127.0.0.1:9025，手机测试使用 9026，不复用用户的 9015/9016 服务。`REPORT_DESKTOP_PORT`、`REPORT_PHONE_PORT` 仅用于显式指定本地测试端口，默认入口和批准机制不变。

### 本地经验与命名

`src/naming.ts` 只处理文件名、日期与页数；`src/learning.ts` 提取 12×8 去均值亮度布局并匹配经人工确认的相对四角，版本化本地存储键为 `talkcapture-corrections-v1`。匹配要求长宽比差小于 2.5%、布局均方根距离不超过 0.035、有足够结构且无相近分数的矛盾经验。这些阈值是工程启发式，不是置信概率。检测器只在 `not_found` 时尝试经验回退，不替换多候选判断。`learnedSuggestion` 页不经人工确认不得自动批处理。手机 ACK 分开携带失败 `reason` 与已导入的 `reviewReason`，均限 300 字符。

### 补传与兼容

`src/recovery.ts` 优先匹配缺图页的内容指纹；同源多个缺图页可以共用一次补传。无指纹旧记录仅在文件名、大小唯一匹配时回退，忽略修改时间；歧义或同名内容变化不自动新增重复页。定向补传允许名称或内容变化，保留 ID、位置、四角和调整，但 `sourceNeedsReview` 要求重新确认，自动批处理暂停。已有原图的同名同内容重复导入不新增页。

启动时从 v1 元数据无损升级，已有原图的页直接可用，旧记录缺图则保留等待补传。JPEG/PNG 缩略图从缓存生成临时 URL；HEIC 在打开时由处理器生成显示预览。元数据错误与原图缓存失败分开显示，手机成功导入 ACK 会等待本页保存尝试完成。没有新增依赖或云端存储。

## MiniMax 报告解读

用户已授权主动点击报告解读时向 MiniMax 发送选中报告的识别文字和来源页码。OCR、原图处理、分组及基础 Markdown 摘录仍在本机完成。

复制 .env.example 为 .env.local 并配置 MINIMAX_API_KEY；配置每次请求读取，环境变量优先。默认模型 MiniMax-M2.5，默认官方国内地址 https://api.minimax.cn/v1，也允许官方 api.minimaxi.com 与国际 api.minimax.io。禁止任意代理地址和 HTTP 重定向，避免密钥外传。不返回上游错误正文，不记录密钥或提示词，不自动重试付费请求。

应用不依赖 Qwen3/Ollama，也没有 Ollama 回退；不要把某台开发机曾停用的服务状态作为仓库安装步骤。模型调用错误时仍可下载本地摘录。无需新增生产依赖。

## 页面设置

`server/model-config.ts` 统一读写电脑端配置；`server/settings.ts` 提供同源且带 `x-desktop-client: 1` 的设置接口，仅返回模型、官方地区和密钥存在状态。保存使用串行队列、同目录临时文件原子替换和0600权限，保留其他配置值，空密钥保留原值。已有启动环境变量时拒绝页面写入，避免界面显示已保存但实际不生效。`POST /api/settings/test` 只发送固定测试文字，仍可能产生 API 费用。

`src/settings.ts` 管理原生 dialog、显示偏好和模型表单。主题和字号只写入 `talkcapture-display`，不会把密钥写入浏览器存储。软件版本由 Vite 从 package.json 读取，构建信息取本次构建时间。测试使用临时配置文件或网络模拟，不修改开发机真实密钥。
